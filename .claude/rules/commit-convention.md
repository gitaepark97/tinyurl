# Commit Convention

커밋 메시지는 다음 형식을 따른다.

```
<type>: <subject>
```

- `type`: 변경 사항의 종류를 나타내는 접두사
- `subject`: 변경 내용을 요약하는 문장. 한글로 작성하며, 마침표는 생략한다.

## Type 종류

| type | 설명 |
| --- | --- |
| `feature` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `hotfix` | 배포된 서비스의 긴급 수정 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `test` | 테스트 코드 추가 및 수정 |
| `docs` | 문서 추가 및 수정 |
| `style` | 코드 포맷팅, 세미콜론 등 로직에 영향 없는 스타일 변경 |
| `perf` | 성능 개선 |
| `chore` | 빌드, 설정, 의존성 등 기능에 영향 없는 잡업 |
| `ci` | CI 설정 및 스크립트 변경 |
| `revert` | 이전 커밋 되돌리기 |

## 예시

```
feature: 단축 URL 리다이렉트 기능 추가
fix: 중복 URL 키 발급 오류 수정
hotfix: 리다이렉트 500 에러 긴급 수정
refactor: URL 서비스 계층 분리
test: 클릭 통계 집계 로직 테스트 추가
docs: API 명세 문서화
style: 코드 포맷팅 정리
perf: 캐시 적용으로 조회 성능 개선
chore: Spring Boot 버전 업그레이드
ci: GitHub Actions 워크플로 추가
revert: "feature: 단축 URL 리다이렉트 기능 추가" 되돌리기
```

## 규칙

- 하나의 커밋에는 하나의 변경 사항만 담는다.
- subject는 "~함", "~추가", "~수정" 등 명사형 또는 서술형으로 간결하게 작성한다.
- 본문(body)이 필요한 경우 subject 다음 줄을 비우고 상세 설명을 작성한다.
- 관련 이슈가 있다면 본문 아래에 빈 줄을 두고 이슈 번호를 남긴다. 예: `Refs #42`
